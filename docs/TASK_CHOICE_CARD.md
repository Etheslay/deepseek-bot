## 0. 背景与问题（为什么有这份任务书）

选项卡片在三个任务里各交付了一半，中间的接线至今无人认领，导致当前可复现的用户可见缺陷：

1. **D14 交付了卡片 UI**（`13acf47`），但报告明确“只做渲染与点击回写会话，未接 `ask_user` 能力”；
2. **D15 落了 `ask_user` 后端**（`0350e40`），报告标注“真实聊天接线待做”；
3. **D30 落了真实聊天运行时**（`chat.send`，真实 Key 验证通过），但只接了输入框路径。

用户可见缺陷（2026-10-26 实测截图）：点击选项后只出现一条“我选择：深度思考一个复杂问题”的用户气泡，**没有任何回复、没有流式气泡、没有失败气泡**。

## 2. 需求清单（FR，验收以逐条打勾为准）

### FR-1 发送文本 = 选项原文

点击 A/B/C 任一选项，发出的用户气泡文本**就是选项原文**（如 `深度思考一个复杂问题`），不带 `我选择：` 前缀、不带任何冒号或符号修饰。发给模型的内容与气泡展示一致。

### FR-2 已答卡片态：保留折叠、去掉“已选择”

选择后卡片保持现有折叠态（图二：绿勾 + 答案文本，卡片高度收起、选项列表隐藏），但**去掉 `已选择：` 四个字和冒号**，仅显示 `✓ {选项原文}`。答案为自由文本说明时显示 `✓ {说明原文}`（超长截断省略，悬浮完整）。

### FR-3 点击选项必须得到回复

`handleChoice` 改为走与输入框 `send()` 完全相同的链路：`service.chat.stream` → Host `chat.send` → Harness → 模型。要求：

- 点击后立即出现与输入框一致的流式气泡；
- 失败（无 Key / `RUNTIME_UNAVAILABLE` 等）出现与其他消息一致的失败气泡，可重试；
- 可取消，行为与输入框一致；
- 实现方式：把 `send()`/`retryStream()` 中重复的流式启动逻辑提取为共享函数（如 `startChatStream(text: string)`），三条路径（输入框、重试、卡片）共用，禁止再复制一份。

### FR-4 模型主动澄清卡（`ask_user` 真实接线）

当 agent 正在处理事务而用户意图不明确时，模型可主动发起澄清卡。完整回路：

1. 模型调用 `ask_user` 工具（问题 + 选项）；
2. Host 把该请求渲染为聊天流中的选项卡片（复用 FR-2/FR-3 的同一卡片组件）；
3. 用户点选（或输入说明）；
4. 答案作为工具结果回给模型，模型**继续当前任务**；
5. 答案进入会话上下文：后续轮次的模型可感知该选择，作为对用户需求的更准确认知（验收见 §5 E2/E3）。

**选项生成质量要求（写入工具描述/系统提示，并作为人工验收项）：**

- A/B/C 是模型基于当前对话上下文推断出的“用户可能想表达的”，必须具体、互斥、可直接点选，禁止泛泛选项；
- **尽量让 A/B/C 中就有用户想要的答案**；
- **D = “以上都不是”**，仅当确实没有一个候选命中时用户才会选 D；
- D 选项的显示文案由 Host 强制为 `以上都不是`（不信任模型给的 D label，保证一致性）；
- 选 D 后卡片不直接结束：聚焦输入框并提示用户用一句话说明真实意图，说明文本作为最终答案回传模型（`allowOther` 语义）。

**触发约束（2026-10-28 增补，负责人裁决）：** `ask_user` 只允许两类场景——(1) 用户意图确实模糊、答案会改变下一步行动时的主动澄清；(2) 会话开局 bot 角色或用途未定时，让用户点选一个具体方向（如"连 GitHub 仓库 / 设计 / 绘画"这类具体选项，与开局命名/定位相关）。禁止闲聊确认、重复追问用户已回答的内容；每次拿到答案直接行动，仅当答案本身出现真实分叉才允许再问。硬上限：同一回合最多 3 次 `ask_user` 成功调用，第 4 次被 Host 应用工具通道以 429 `RATE_LIMITED` 拒绝（回合继续，模型应改为直接作答）；同一 callId 重放返回已记录结果、不重复计数。上限实现于 `packages/host/src/app-tool-channel.ts`（`MAX_ASK_USER_PER_TURN`），触发场景写于工具描述（`packages/agent-tools/src/ask-user.ts`）。

**等待/取消/过期：** `AskUserCoordinator` 已有 30 分钟超时与取消语义（`packages/agent-tools/src/ask-user.ts`，`WAIT_TIMEOUT_MS`、`expiresAt`、`cancel`）。卡片需呈现过期/取消态（选项禁用 + 一行过期提示），不得停留在可点击状态。

### FR-5 一卡一答与“其他，我说明”

- 每张卡只能作答一次：点击即锁定，全部选项（含 D 与“其他”）立即禁用；
- “其他，我说明”（种子引导卡）/ 选 D（模型澄清卡）都进入自由输入：聚焦输入框、发送后作为该卡答案，走 FR-3 同一链路；
- 多张卡并存时互不影响（现有 `answeredChoices` 按 `msgId` 键控，保持）。

### FR-6 持久化

- **Host 侧**：`ask_user` 的问答随 `chat.send` 现有落库路径持久化（用户答案以用户消息落库，卡片问题随助手消息落库），保证重启后模型上下文不丢失；
- **渲染层**：已答状态本次仅会话内存态（现状即如此）；`chat.history` 回放时恢复卡片已答态与 `chat.history` 回放接线同批处理，**不阻塞本次验收**，但须在报告中如实标注为未验证项。

### FR-7 来源标记（可选增强，默认不做）

如需在 Host 侧区分“卡片作答”与“手动输入”（用于审计/去重），可为 `chat.send` 增加附加式可选字段（如 `source: { kind: "choice_card", cardId, optionId }`）。**涉及契约扩展，须契约负责人（Etheslay）自审后方可实施**；默认推荐本次不做，纯文本即可。

### FR-8 可访问性与主题

- 选项行是真实 `button`，支持 Tab 聚焦 + Enter 选择，焦点环可见；已答/禁用态对读屏可感知（`aria-disabled`/`aria-pressed`）；
- 颜色全部走现有主题变量（深浅主题 + bot 强调色），不写死色值；
- 卡片在流式回复进行时的表现与输入框发送一致（不互相打断）。

## 3. 界面规格（对照需求方截图）

**未选态（图一）：** 保持现状 —— 问题标题 + A/B/C 选项行（字母徽标 + 文案）+ 尾部兜底行。种子引导卡兜底行文案 `其他，我说明`（铅笔图标）；模型澄清卡兜底行为 D 选项，显示文案强制 `以上都不是`。种子引导卡（`App.tsx:846-865`）选项不变。

**已答态（图二）：** 卡片收起为单行 `✓ {答案原文}`。**删除 `已选择：` 前缀**（FR-2）。绿勾、灰底、圆角样式保持现状。

**点击选项后：** 用户气泡（选项原文）+ 立即出现的流式回复气泡（FR-3），卡片同步折叠为已答态。

**选 D / “其他”后：** 输入框聚焦并出现提示（如“请用一句话说明”），用户发送的说明即该卡答案；卡片折叠为 `✓ {说明原文}`。

**过期/取消态：** 选项禁用置灰 + 单行提示（如“该问题已过期，可直接输入补充”）。
