## 3. 中文字体缺失时不得假装已经嵌入

**现象（基线源码）**

`packages/host/src/presentation-font.ts` 的 `embeddedFaces` 只在本机找到并成功子集化一份中文字体时才返回 `cjk`。找不到时 `cjk` 为 `undefined`。

`packages/host/src/presentation-write.ts` 的 `buildPptx` 仍把主题里的东亚字体写成 `faces.cjk?.family ?? "Microsoft YaHei"`。字形列表只收录真正嵌入的脸。结果是：文稿指定了微软雅黑，文件里却没有这份字体。换一台没有雅黑的电脑打开，汉字靠对方系统碰运气。

**做法**

1. 抽出一个纯函数，输入是「文稿文本」和「是否嵌入了中文脸」。文本里有汉字（或假名、韩文）且没有中文脸时，返回一条可展示的失败，`write_presentation` 不写文件。
2. 没有这些字符时，维持现在的西文嵌入，不因为机器没有中文字体而拒绝英文稿。
3. 失败信息写明缺的是本机中文字体，并列出代码已经会查找的那些路径（雅黑、Noto、文泉驿、Droid）。不要把失败写成「已嵌入微软雅黑」。
4. 不在本任务里把一整套中文字体打进安装包。那会带来体积和许可证，要另开任务。

**验收**

- 纯函数：含汉字且无中文脸 → 失败；只有英文且无中文脸 → 通过；含汉字且有中文脸 → 通过。
- 现有「嵌入了真实中文脸」的测试仍通过。
- 不调用 DeepSeek API，不要求本机一定装着雅黑。
