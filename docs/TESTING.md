状态：开发验收计划。当前项目无应用代码，没有应用测试或构建结果。文档检查通过不能替代产品测试。

## 1. 分层策略

| 层级 | 覆盖内容 | 主负责人 |
| --- | --- | --- |
| 静态检查 | 格式、lint、类型、依赖/锁文件、契约与文档链接 | 双方，各自模块 |

## 3. 检查策略

每个 feature 必须静态检查、受影响单元/组件测试、契约测试；涉及跨模块还要集成测试。develop 每次合并执行完整常规回归；release/hotfix 的 main PR 额外执行真实 API 冒烟、最终包验收、迁移与回滚演练。

应用脚本与工具尚未创建，不提供虚假的 `pnpm test` 已可用说明。D01 / D02 建立必要验证，D11 将确定命令写入 CONTRIBUTING 并配置[仓库检查名](REPOSITORY_SETUP.md)。

对可测试运行时模块建议行覆盖率 ≥ 80%，权限与状态机分支覆盖率 ≥ 90%；覆盖率不能代替 QA-07 至 QA-12 的行为测试。排除生成文件需记录理由。

## 4. 测试证据格式

每条证据包含：任务/PR、提交 SHA、测试命令或手测步骤、运行时间、系统/硬件、结果、日志/截图路径、失败项与负责人。真实 API 还记录模型标识与测试预算，不保存 Key。

P0：数据丢失、凭据泄露、越权执行、不可安装等发布阻断；P1：主路径失效、取消失效、重要迁移错误，必须修复；P2：有替代路径的非核心问题，可以书面记录为已知问题，由双方接受后发布。
